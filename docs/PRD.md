# 제품 요구사항

## 경험과 대상

친구나 소규모 팀이 링크로 모여 한 판을 즐긴다. 엑셀에서 익숙한 열 머리글, 행 번호, 수식 표시줄, 시트 탭으로 게임 진행과 커뮤니티를 한 화면에 정리한다. 회사와 부서는 게임 속 소속이다. 첫 방문자는 방 참가 → 첫 굴림 → 점수 확정까지 도움말 없이 도달할 수 있어야 한다.

| 단계 | 범위 | 출시 기준 |
|---|---|---|
| 목업 | 로비·게임·채팅·조직·상점·내 사무실 | 로컬에서 핵심 흐름을 클릭으로 시연 |
| MVP | 소셜 인증 및 사원 등록, 2–4인 방, 12카테고리 대전, 방 채팅, 재접속 | 두 브라우저에서 시작부터 공동 결과 확인 |
| 성장 | 회사 클랜·초대·랭킹, 재화·상점, 직급·칭호 | 중복 보상과 구매 경쟁을 테스트로 차단 |
| 3D | 아바타, 개인 사무실 배치 | 저장 후 다른 세션에서 복원, 2D 대체 화면 제공 |

## 사용자 흐름

- **입장** 방 목록에서 입장하거나 방을 만들고 링크를 공유한다. 준비 상태가 표시되며 방장이 시작한다.
- **대전** 활성 플레이어와 남은 시간이 표시된다. 굴림 후 보관할 주사위를 고르고, 선택 가능한 점수를 미리 본 뒤 한 칸을 확정한다.
- **결과** 총점과 공동 순위를 보여준다. 성장 단계부터 보상 원장과 연결한다.
- **커뮤니티** 방 안에서 채팅하고, 성장 단계에서 가상 조직 가입과 칭호 장착을 할 수 있다.
- **꾸미기** 코인으로 장식을 구매하고 보유 목록에 반영한다. 이후 3D 사무실에서 실제 배치를 저장한다.

## 화면과 수용 기준

| ID | 기준 |
|---|---|
| UX-01 | 시트 이름과 활성 셀이 표시된다. 좁은 화면에서 점수표를 가로 스크롤하고 턴 제어는 계속 접근할 수 있다. |
| UX-02 | 현재 플레이어·굴림 횟수·잠금 상태를 텍스트로 확인할 수 있다. 점수 칸은 키보드로 선택할 수 있다. |
| GM-01 | 서로 다른 브라우저에서 주사위·점수·결과가 일치하고, 새로고침 뒤 현재 턴을 복원한다. |
| CH-01 | 같은 방 멤버만 메시지를 읽고 보낼 수 있다. 오류와 재시도 상태를 표시한다. |
| OR-01 | 사원 담당 부서는 최초 등록 시 선택·직접 입력하고, 회사 클랜은 최대 하나에 가입한다. |
| EC-01 | 잔액 부족, 중복 요청, 이미 보유한 아이템을 테스트하고 원장과 잔액이 일치한다. |
| 3D-01 | 저장한 배치를 복원하고, WebGL 초기화에 실패하면 2D 보유 목록을 사용할 수 있다. |

초기 범위는 한국어 데스크톱 웹 중심이다. 현금 결제·환전·아이템 거래·음성채팅은 범위 밖이다. 제품 검증 지표는 입장→첫 점수 확정률, 시작→완주율, 재접속 복구율이다. 목표치는 플레이 테스트 이후 정한다. 게임 규칙·권한·보상 수치는 아래 명세의 초안이다.

## 2026-11-09 중간 합의

엑셀 업무 문서 UI를 사용하며 버튼과 호버 설명은 실제 기능을 알려준다. 게임방 리더는 프로젝트 리더(PL), 회사 클랜 소유자는 대표다. 2~4인 평가실에서 초대 수락과 참여자 준비를 확인하고 PL만 시작한다. 목업을 Codex에서 계속 검토하는 동안 Claude는 PostgreSQL·Redis 개발 인프라를 구성한다.
