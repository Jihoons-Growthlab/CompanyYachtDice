# 로비와 게임방

방 목록은 대기 중인 공개 방만 표시한다. 비공개 방은 추측하기 어려운 초대 링크로 입장한다. 방 이름 1–40자, 정원 2–6(2026-11-09 사용자 요청으로 최대 6명 통일, 정책 값 `game.policy.ts`). 방 상태는 WAITING → PLAYING → CLOSED. 매치 종료 시 결과를 계속 읽을 수 있다. 신규 좌석 배정은 WAITING에서만 허용한다.

입장 트랜잭션은 방 잠금 아래 정원과 사용자 중복을 검사한다. 방장 외 전원이 준비 상태이며 참가자가 2명 이상이면 방장이 시작할 수 있다. 대기 중 방장이 나가면 가장 오래된 잔여 멤버에게 권한을 위임하고 빈 방은 닫는다. 플레이 중 좌석은 결과까지 유지한다. 연결 종료는 소켓 연결 상태만 바꾼다.

로비는 빈 목록과 정원 초과를 구분한다. 게임 화면은 열 머리글, 행 번호, 카테고리, 플레이어별 점수, 소계·보너스·총점과 수식 표시줄을 사용한다. 선택 셀과 확정된 0을 명확히 표시한다. 새로고침은 동일 세션으로 구독과 스냅샷을 다시 받는다. 동시 입장 경쟁에서 정원 초과가 생기지 않는지 검증한다.


## 평가실 대기 흐름 · 중간 확정

방장은 UI에서 프로젝트 리더(PL)로 표시한다. 참여자 목록에 사원명, 담당 부서, PL 여부, 준비 상태와 빈 좌석을 표시한다. PL은 정원을 2~4명으로 정하고 특정 사원에게 참석 요청을 보낸다. 대상 사원이 수락하면 서버가 WAITING과 남은 정원을 재검사해 좌석을 배정한다. 초대 발송은 좌석 확보를 보장하지 않는다.

최소 2명, 정원 이하, PL 외 참여자 전원 준비 완료일 때 PL만 시작한다. 참여자는 준비를 해제할 수 있다. 서버가 입장·수락·정원 변경·준비 변경·시작 경쟁을 직렬화한다. 이미 입장한 인원보다 낮은 정원을 설정할 수 없다. 초대 수락 재시도는 중복 좌석을 만들지 않는다. 진행 중인 방은 신규 입장을 허용하지 않는다.

현재 시연은 초대 수신자와 PL 시점을 브라우저에서 전환하며 상대 사원은 시작 후 로컬 봇으로 진행한다. 실제 사용자에게 초대를 전달하고 권한을 검증하는 기능은 서버 후속 구현이다.
